# 桌面启动所需文件与公开状态

此前 SDK / IIG Release 补齐的是构建依赖，不能独立组成能启动桌面的系统。此次固定 u88 运行包补齐下面的运行文件。

| 依赖 | 此前缺口 | 本次运行包 |
| --- | --- | --- |
| 预链接内核 `kernel.macho` | 只有源码、配方、哈希，未提供实际桌面内核 | 提供 u85～u88 同一份 56,590,336 字节实测输入 |
| `MIX4-UniXNU-desktop-u88-boot.img` | 缺包含固件 / BDS / 供盘协议的约 2 MB RAM 启动镜像 | 提供原始完整镜像 |
| core7 驻留 DarwinBoot | 通用入口不能代替板级驻留流程 | 提供匹配的 ARM64 EFI 文件，固件中也含配套模块 |
| ADT `kernel.macho.adt` | DTS 源码不等于原实测二进制 ADT | 提供匹配的最终 ADT |
| u88 System | 此前只提供 u80 的获取 / 生成资料 | 提供 u88 System 分卷，下载工具还原为完整文件 |
| Data | 缺初始化后的可启动测试 Data | 提供离线 QEMU 测试 Data，不使用个人手机 Data 分区 |
| trust | 只有部分历史 trust 元数据，未配齐 u88 | 提供与 u88 辅助库匹配的 development trust |
| `unixnu.toml` | 已有配置，但使用者可能仍载入默认文件 | 放入完整运行目录并校验哈希 |
| USB 供盘 | 原脚本依赖历史目录、manifest 和设备序列号 | 新工具使用相对路径和使用者序列号 |
| UI idle 请求 | 原实测依赖及时请求，单拷文件容易漏掉 | 新工具在 post-VM 后、辅助库启动前发出固定请求 |

安装与使用：[u88 桌面运行包](DESKTOP-U88-RUNTIME.md)。

## 仍未完成的源码重建闭环

运行包冻结现有可用输入，不代表以下源码问题已经解决：

- 从 Apple IPSW 重建历史基础 `system.apfs` 的全部独立来源记录仍不完整；u59 → u80 的隔离重放已通过，但没有从 Apple 下载开始完成全链同哈希重建。
- 初始 Data 的目录骨架、扩容、setup preferences 和首次启动状态有历史脚本及本地产物，尚无全新环境的一条完整可验证生成入口。
- 部分显示 / HID / 存储 ABI、provider archive 和历史编译记录仍依赖固定开发环境；不能以 SDK / IIG 已提供为由推断其他输入全部齐全。
- 固件重建脚本依赖本地 Mu 工作树、保留固件基线、141 个原模块、MMCX/RPMh provider、工具链与 fingerprint 数据。运行包提供其已构建 boot.img，尚未把所有底层固件输入整理成 fresh clone 重建方案。
- 当前没有在第二台设备完成从公开 Release 下载到桌面的独立验收。若无法启动，应提交新启动工具的日志，而不是沿用早期诊断镜像的结果。

其他机型仍需各自平台、固件、ADT、内核和外设适配，不能直接使用 MIX 4 的运行包。
