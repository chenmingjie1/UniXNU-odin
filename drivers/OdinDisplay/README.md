# MIX 4 display interface for iOS 16.5

Current computer-only stage: u25. Original display start and GOP mapping work;
u20's exact `chosen/display-scale` reader fixes the observed mode assertion.
u24's AppleKeyStore class registration and original `AppleKeyStoreUserClient`
name allow six observed opens and successful state selectors 0/7/17/35 through
the original client policy. This is ephemeral RAM state, never key storage.

`OriginalSurface16.h` binds actual original iOS16 getters. The source property
stores independently establish width144, height148, stride152, format164 and
allocation172. Backing memory is +56; +48 is a map. Compiled getLength/prepare/
complete calls agree with the original IOSurface's memory dispatch. The audit
is `scripts/audit_ios16_surface.py`; final aliases and compiler calls are also
checked in `audit_odin_display_link.py`.

With `odin-surface-inspect=1`, exact slot282 inspects up to four original
surfaces and records bounded metadata. It returns false: queue ownership,
producer synchronization, presentation and retirement remain unimplemented.
No desktop or device support is claimed. Earlier stages follow below.

The opaque superclass is generated by `prepare_odin_display_interface.py` from
the exact original family audited by `audit_odin_display_abi.py`.

`OdinDisplayABIAnnotation.cpp` is a compiler annotation only. It is never linked,
executed, registered, or shipped in a phone image. It verifies the 0x1660-byte
class and 338-entry vtable against the actual source-kernel compiler.
The nine unqualified abstract leaves trap rather than inventing return values.

The upstream GopFramebuffer implementation is a porting reference. Its 358-entry,
0x18a0-byte iPadOS layout is incompatible and has not been copied into this ABI.
`OdinLegacyGOPDisplay.cpp` implements the qualified slot-274 GOP mapping entry
and uses the original slot-246 geometry reader. Its private dimension fields
5208/5212 are checked against original instructions. It accepts only matching,
bounded 32-bit unrotated firmware memory, gated by `odin-gop-display=1`.
`OdinDisplayOwner.cpp` registers the exact superclass after original family
initialization, creates an actual IOPlatformDevice/IODeviceMemory provider, and
invokes original probe/attach/start. It is gated off unless
`odin-gop-display=1` is explicitly present. u15 computer replay completed
original start and mapped the 1080x2400 framebuffer; actual user-client access
then hit the original provider's null AppleARMIODevice field.

u16 qualifies selector28 / slot188 / uint32 output against the exact original
instructions and returns the original missing `dot-pitch` result (0xe00002f0)
for GOP, which has no physical density. It does not claim an Apple hardware
identity. Final linked dispatch is independently checked; see
`build/display-owner-u16/display-link-audit.json` and the runtime progress.
Neither version is a phone-qualified desktop image.

Its 300-second replay did not panic, but the inspected framebuffer contains only

Main-display discovery, original IOSurface backing, client operations,
